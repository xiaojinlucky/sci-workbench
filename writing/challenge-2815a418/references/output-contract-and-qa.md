# Output Contract Specification and Pre-Seal QA (`rebuttal-revision-closure`)

## 1. Required Deliverables Under `/app/output/`

1. `/app/output/result.json` — Structured final record containing all 5 original `output_contract` fields plus runtime status and provenance.
2. `/app/output/manuscript-revised.md` — Editable revised version of `/input/materials/manuscript-baseline.md` implementing every feasible change.
3. `/app/output/response-letter.md` — Point-by-point response letter covering every comment ID and sub-requirement with canonical disposition tags, exact `[§Section Lx-Ly]` anchors, and verbatim quoted excerpts.
4. `/app/output/missing_evidence_list.md` — Tri-partite ledger of all `AUTHOR_INPUT_NEEDED`, `PARTIAL`, `NOT_FEASIBLE`, or `OUT_OF_SCOPE` items (or explicit confirmation of zero pending evidence gaps).
5. `/app/output/rebuttal_ledger.json` — Machine-verified audit output from `scripts/rebuttal_closure_checker.py`.
6. `/app/output/rebuttal_closure_report.md` — Human-readable closure table and diff/tone audit summary from `scripts/rebuttal_closure_checker.py`.

## 3. Pre-Seal Verification Gate

Before finishing, verify every box:
- `rebuttal_closure_checker.py` returned exit code `0` (`"passed": true`).
- Every `metrics` key in `result.json` has a matching entry in `metric_provenance`.
- Every DOI/arXiv ID in `result.json` exists in `/input/` (`gap_gate.py` returns `0`).
- Zero raw placeholder strings (`TO`+`DO`, `TB`+`D`, `FIX`+`ME`, `[insert ...]`) appear anywhere in `/app/output/` (`final_audit.py` returns `0`).
- If any item is `AUTHOR_INPUT_NEEDED` or `PARTIAL` with unresolved author evidence, `gaps` is non-empty and `status` is `"partial_with_gaps"`.
